## 背景：为什么要"非递归"

人的直觉适合递归：写出 `calc(x)` 让系统自己压栈、自己回溯，逻辑干净。但系统栈在给你擦屁股——**存参数、记返回地址、恢复现场**，这几件事它都替你做了，于是递归的执行过程变成黑盒：你知道它对了，但看不见它怎么对。

把递归改写成非递归（模拟栈），本质就是**把黑盒打开**：用一个数组 `stack[]` 手动压帧，用一个变量 `address` 当程序计数器，让"函数调用"的每一步都摊在桌面上。

演示用《算法竞赛进阶指南》的经典例题：**组合型枚举**（从 n 个里选 m 个，输出所有组合，AcWing 93 风格）。

## 核心思想：三件事 + 三态机

递归时每个函数调用需要三样东西：参数、返回地址、现场。对应地，代码里每个 `call(x, ret_addr)` 往栈里压 **3 个槽**：

```
┌─────────────┐
│ 参数 x       │  ← 栈顶第 -2 槽
│ 返回地址     │  ← 栈顶第 -1 槽
│ 旧 top       │  ← 栈顶第 0 槽
└─────────────┘
```

而 `address`（程序计数器）只可能有三个值，因为递归体只有三个"位置"：

| 递归 calc(x) 里的动作 | 模拟栈版本 |
|---|---|
| 函数入口 | case 0 |
| 开头的剪枝 return | case 0: `address=ret(); continue;` |
| x==n+1 输出后 return | case 0: 输出后 `address=ret(); continue;` |
| calc(x+1) —— 不选分支 | case 0: `call(x+1, 1); address=0;` |
| push_back(x) —— 选 x | case 1 |
| calc(x+1) —— 选完再往后 | case 1: `call(x+1, 2); address=0;` |
| pop_back() 后 return | case 2: `pop_back(); address=ret();` |

注意 `address = ret()` 的返回值**由调用者决定**：被 case 0 调进来回 1，被 case 1 调进来回 2，被 main 调进来回 0（栈空，程序结束）。子函数不能决定自己回来后干嘛——这是真递归里"子函数 return 后父函数继续执行它的下一行"在模拟栈里的形态。

## 怎么读这个演示

盯住三处联动：

1. **栈（左上）**：每一次 `call` 多一帧，每一次 `ret` 少一帧；每帧标着 `参数 x / 返回 case / 旧 top`。
2. **address（右上）**：它决定当前执行哪个 case。跳成 1 = 要选数了，跳成 2 = 要撤销了，跳成 0 = 新层开始。
3. **chosen（中间）**：绿色数字进出，就是 `push_back` / `pop_back`。

一个容易疑惑的点：演示里会出现 `x=5`——这不是"选第 5 个数"，而是**哨兵**。x 是从 1 数到 n+1 的决策游标，走到 n+1 表示 1..n 全部决策完毕，该输出当前 chosen 了；所以输出帧的 x 全是 5，而 chosen 里永远不会有 5。

## 结尾

把递归改成模拟栈，难的不是代码，是把"系统替你做的三件事"认出来。一旦认出来，后面所有递归（全排列、八皇后）都是同一套模板：压帧、计数、回溯。
